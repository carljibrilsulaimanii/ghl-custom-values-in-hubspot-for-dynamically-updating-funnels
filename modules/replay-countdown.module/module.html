In use on: the replay sign-in page. WHAT IT DOES Same show/hide engine as Watch Page Counter, with two differences. 1. The clock targets the end of the replay window instead of the class start: class time on old_class_date + 72 hours (minus Offset minutes). While the clock runs the replay is open; at zero it closes: - "Unhide While Active / Hide at 0" selectors hide (the form) - "Hide While Active / Unhide at 0" selectors show (expired copy) - the clock hides - if the config has a Registration Page URL, the visitor is sent there (query string carried; never in the editor or a preview) 2. "Ignore countdown - keep replay open" (force_open) keeps the page in its open state no matter what the clock says, before or after zero: the form stays visible and only the clock hides. Set it on every instance on the page. "Selector - Hide when toggle is on" hides extra elements in that state (e.g. the "Replay Expires In:" label). TIME OF DAY old_class_date is a *date* property: HubSpot stores it as midnight UTC, with no time. The module anchors it to the class time in New York: - hour from the config's class_time ("7pm EST", "12pm EST"; minutes ignored), falling back to 7pm if it can't be read, - EDT/EST worked out for that date, so nothing changes by hand on the DST switch. Offset minutes is only a fine-tune on top (positive = earlier, negative = later). Leave it at 0. WHY THESE CHOICES - crmobject_field fetches old_class_date. Fetching only event_start_date_and_time left the date empty and the clock blank. - force_open keeps the open state (form visible) rather than forcing the zero state, which hid the form on the replay page. - Class time + New York DST are computed in HubL, replacing a manual minutes-offset convention that broke on every DST switch. - At zero the visitor is redirected to the config's registration_page_url.
